Kruskal: chamadas à estrutura

  • makeSet: $V$ vezes (uma por vértice).
  • findSet: 2 por aresta examinada, ou seja $2A$.
  • union: $V-1$ vezes (uma por aresta aceita).

Implementação 1: listas ligadas

  • Conjunto S: head, tail (+ size na união ponderada). Nó: valor, next, rep → S. Representante = head.
  • Vetor ptr[x] → nó de x (acesso O(1) pela chave).
union(x, y)
Sx = findSet(x); Sy = findSet(y)
if Sx.size < Sy.size then trocar(Sx, Sy)   ▸ só na ponderada
Sx.tail.next = Sy.head
Sx.tail = Sy.tail
Sx.size = Sx.size + Sy.size                   ▸ só na ponderada
for each z em Sy do z.rep = Sx                ▸ domina: O(|Sy|)

Implementação 2: floresta (vetor pai)

  • Cada conjunto é uma árvore; nó aponta para o pai; raiz: pai[r] = r; raiz = representante.
  • Ler o array: raízes são os i com pai[i] = i; seta i → pai[i].
  • findSet faz profundidade(x) + 1 chamadas.
makeSet(x): pai[x] = x
findSet(x)
  if pai[x] = x then return x
  return findSet(pai[x])
union(x, y): pai[findSet(x)] = findSet(y)      ▸ raiz → raiz

Union by rank

makeSet(x): pai[x] = x; rank[x] = 0
union(x, y)
  rx = findSet(x); ry = findSet(y); if rx = ry return
  if rank[rx] < rank[ry]: pai[rx] = ry
  else if rank[rx] > rank[ry]: pai[ry] = rx
  else: pai[rx] = ry; rank[ry]++        ▸ só o empate aumenta o rank
  • rank da raiz = altura da árvore (sem path compression). Só ranks de raízes são comparados.
  • Altura h exige ≥ $2^h$ nós (só sobe unindo duas de altura h−1) ⇒ $2^h \le n$ ⇒ $h \le \log_2 n$.

Path compression

findSet(x)
  if pai[x] ≠ x then
      pai[x] = findSet(pai[x])      ▸ na volta: aponta direto para a raiz
  return pai[x]
  • Só altera pai dos nós do caminho; rank não muda e vira limite superior da altura.
  • Rank + compressão: 1 chamada ainda $O(\log n)$ no pior caso; $m$ operações $O(m\,\alpha(n))$; $\alpha(n) \le 4$ na prática (α = inversa de Ackermann).
  • α: n = 2, 3, 7, 2047, 10⁶, 10⁸⁰ → 0, 1, 2, 3, 4, 4.

union errados: pai[x] = y (ancestrais de x ficam fora); pai[findSet(x)] = y (correto, mas a árvore fica alta).

Complexidade de Kruskal e Prim

O quêCustoPor quê
Listar arestas: matriz$O(V^2)$olha todas as células
Listar arestas: listas$O(V + A)$V cabeças + 2A itens
Kruskal$O(A \lg A)$$O(V) + O(A\lg A)$ ordenação $+ O(A\,\alpha(V))$; $A \ge V-1$
Prim (listas + heap)$O(A \log V)$V extractMin + até A decreaseKey, cada $O(\log V)$; 2A visitas em Adj
Prim (matriz + heap)$O(V^2 + A\log V)$linha 8 olha V células por vértice
Prim (heap de Fibonacci)$O(A + V\log V)$só citado no slide

Heap binário: altura ⌊log₂ n⌋ sempre (nunca desbalanceia). $\lg A \le 2\lg V$, então Kruskal e Prim têm a mesma ordem.
