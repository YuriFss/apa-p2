Aula 11 · Lição 3

Union by rank

Primeira heurística da floresta. Ela decide qual raiz fica embaixo no union e, com isso, garante altura $\le \log_2 n$. Assim findSet e union passam de $O(n)$ para $O(\log n)$.

2. O problema: quem fica embaixo importa

Na Lição 11.2, o union do slide faz pai[findSet(x)] = findSet(y): a raiz de x sempre vai para baixo da raiz de y. Ele ignora o tamanho das árvores. Veja as duas formas de juntar estas árvores:

Antes: árvore de raiz 2 com altura 2 e árvore de raiz 5 com altura 1.

pai[5] = 2: a mais baixa embaixo da mais alta. Os nós da árvore do 5 descem 1 nível e ficam na profundidade 1 + 1 = 2. Altura continua 2.

pai[2] = 5: a mais alta embaixo da mais baixa. O nó 1, que estava na profundidade 2, vai para 3. Altura sobe para 3.

Regra

Pendurar uma árvore embaixo de uma raiz aumenta em 1 a profundidade de todos os nós dela. Se ela for a mais baixa, isso não ultrapassa a altura da mais alta. É a mesma ideia da união ponderada das listas (Lição 11.1: anexar a menor à maior). Aqui a medida não é o tamanho, é a altura.

3. O que é o rank e o pseudocódigo

Definição (slide "Union by rank")
  • Além de pai[x], cada elemento guarda rank[x].
  • Para uma raiz, o rank é a altura da sua árvore (a profundidade do nó mais fundo).
  • O rank só importa para raízes: o union só compara ranks de raízes. Quando um nó deixa de ser raiz, o rank dele nunca mais é lido nem alterado.
  • union(x, y): acha as duas raízes e faz a de menor rank apontar para a de maior rank.
makeSet(x)
1.  pai[x] = x
2.  rank[x] = 0      ▸ 1 nó: altura 0
union(x, y)
1.  rx = findSet(x)
2.  ry = findSet(y)
3.  if rx = ry then return
4.  if rank[rx] < rank[ry] then
5.      pai[rx] = ry          ▸ rx é a mais baixa
6.  else if rank[rx] > rank[ry] then
7.      pai[ry] = rx          ▸ ry é a mais baixa
8.  else                      ▸ empate
9.      pai[rx] = ry
10.     rank[ry] = rank[ry] + 1

No empate qualquer escolha serve, desde que se incremente o rank da raiz que ficou em cima. A convenção acima é a do slide (e do Cormen): a raiz de x desce.

5. A simulação do slide: 8 elementos, 7 unions

Começa com 8 elementos separados (pai[i] = i, rank[i] = 0) e executa union(0,1), union(2,3), union(1,3), union(4,5), union(5,0), union(6,7), union(7,2). Repare em quando o rank aumenta (só nos empates) e em quando não aumenta.

Em union(5, 0), findSet(0) não devolve 0, devolve 3: o 0 já estava na árvore do 3 (0 → 1 → 3). O union by rank compara os ranks das raízes, nunca os dos elementos passados como argumento.

6. Por que a altura nunca passa de log₂ n

Pelo slide: vamos tentar construir a árvore mais alta possível. Com union by rank, a altura de uma árvore só cresce num empate. Então, para chegar à altura $h$, é preciso unir duas árvores de altura $h-1$:

Construindo a árvore mais alta com 8 elementos

Sequência: union(0,1), union(2,3), union(4,5), union(6,7) (quatro árvores de altura 1), depois union(1,3), union(5,7) (duas de altura 2) e union(3,7) (uma de altura 3). Mesmo forçando, 8 nós dão no máximo altura 3 = log₂ 8.

Altura $h$0123⋯$h$
Nós (no mínimo)1248⋯$2^h$
Argumento completo (resposta de prova)

Afirmação: uma árvore de altura $h$ construída com union by rank tem pelo menos $2^h$ nós.

  • Base: $h = 0$ é um nó só, e $1 = 2^0$.
  • Passo: a altura só aumenta, de $h-1$ para $h$, quando se unem duas árvores de altura $h-1$ (empate). Cada uma tem pelo menos $2^{h-1}$ nós, então a nova tem pelo menos $2 \cdot 2^{h-1} = 2^h$. Unir com uma árvore mais baixa não muda a altura e só acrescenta nós.

Conclusão: com $n$ nós no total, $2^h \le n$, logo $h \le \log_2 n$. Os nós são consumidos de forma exponencial ($2^h$) enquanto a altura cresce de forma logarítmica.

7. Novas complexidades

findSet custa a profundidade, que agora é no máximo $\log_2 n$. union são dois findSet mais $O(1)$:

Função (pior caso)Listas ligadasFlorestaFloresta + union by rank
makeSet$O(1)$$O(1)$$O(1)$
findSet$O(1)$$O(n)$$O(\log n)$
union$O(n)$$O(n)$$O(\log n)$

O slide destaca: mesmo com union by rank, a árvore pode chegar à altura $\log_2 n$ (a construção da seção 6), então $O(\log n)$ é justo. Fazer melhor exige a segunda heurística, path compression (Lição 11.4).

Exercício 11.3

Floresta com 8 elementos (0 a 7), inicialmente com pai[i] = i e rank[i] = 0. Execute com union by rank (no empate, a raiz de x desce):

union(0,1), union(2,3), union(0,2), union(4,5), union(6,4), union(7,0)

  3. Execute a mesma sequência sem union by rank (pai[findSet(x)] = findSet(y)). Qual a altura final?
