Heurística do vizinho mais próximo

A ideia mais natural: de onde você está, vá para a cidade mais perto que ainda não visitou. Nesta lição: a execução passo a passo, por que o resultado depende da cidade inicial, onde a gulosa erra e o custo $O(n^2)$.

1. Exemplo resolvido

Mesma matriz da lição anterior. Saímos de A. Em cada linha, olhamos a linha da cidade atual na matriz, só nas cidades ainda não visitadas.

Estou emNão visitadas (distância)Vou paraCusto acumulado
AB 3, C 4, D 2, E 7D2
DB 7, C 5, E 6C2 + 5 = 7
CB 4, E 7B7 + 4 = 11
BE 3E11 + 3 = 14

Tour: A → D → C → B → E → A, custo 21. A última linha é a volta para casa. Ela faz parte do tour e é fácil de esquecer.

2. O algoritmo

Pseudocódigo do slide:

procedimento HVM(j)
1: Inicialize a solução apenas com o vértice j
2: Se todos os vértices foram visitados, retorne a solução e termine.
3: Adicione à solução o vértice i que ainda não foi visitado e que está
   mais próximo do último vértice visitado (o vizinho mais próximo).
4: Retorne para a linha 2.

A mesma coisa com laço e variáveis. Esta versão é a que usamos para contar o custo. Clique em "próximo" e acompanhe a matriz:

3. A cidade inicial importa

Rodando a partir de cada cidade (use os botões acima para conferir):

InícioTourCusto
AA → D → C → B → E → A21
BB → A → D → C → E → B20
CC → A → D → E → B → C19
DD → A → B → E → C → D20
EE → B → A → D → C → E20

Saindo de C, achamos 19. Esse é o ótimo desta instância (a força bruta confirma). Saindo de A, achamos 21.

Variante

Rodar o HVM a partir de todas as n cidades e ficar com o melhor tour. Custa n vezes mais: $O(n^3)$.

4. Onde a gulosa erra

HVM a partir de A: 21. A última aresta, E → A, custa 7.

Ótimo: 19. Não usa A–E.

No começo, o HVM pega as arestas baratas: 2, 5, 4, 3. Mas ele nunca olha para frente. Quando acaba, está em E, longe de A, e é obrigado a pagar a volta.

Isso é típico de algoritmo guloso: as escolhas boas do início deixam as cidades "difíceis" para o fim. No exemplo do slide, com cerca de 50 cidades, o HVM dá 497. O ótimo é 413.

5. Complexidade

Use a versão com laço da seção 2. Com a matriz, ler $c[u][v]$ custa $O(1)$.

LinhaQuantas vezesCusto de cadaTotal
1–2. tour = [j], marque j (vetor marcado com n posições)1$O(n)$$O(n)$
3. while existe não marcadan − 1$O(1)$ com um contador$O(n)$
4. achar a não marcada mais perto de un − 1percorre as n cidades: $O(n)$$O(n^2)$
5–6. adicionar, marcar, andarn − 1$O(1)$$O(n)$
7. fechar o ciclo1$O(1)$$O(1)$
Total$O(n^2)$

O que domina é a linha 4: n − 1 buscas, cada uma olhando n cidades.

E com listas de adjacência? No grafo completo, cada lista tem n − 1 vizinhos. A linha 4 percorre a lista de u: continua $O(n)$. O total continua $O(n^2)$. A diferença está na linha 7: achar $c(u, j)$ exige percorrer a lista de u, que é $O(n)$ em vez de $O(1)$. Isso não muda o total.

Na prova, escreva
  1. O pseudocódigo com o laço e uma frase: "a partir da cidade atual, vá para a não visitada mais próxima; no fim, volte à inicial".
  2. O laço roda n − 1 vezes; cada busca percorre n cidades; logo $O(n^2)$.
  3. A representação: matriz dá acesso $O(1)$ a $c[u][v]$; listas também dão $O(n^2)$ no grafo completo.
